# 踩坑清单

按"症状 → 原因 → 修法"写。带 ⭐ 的是**一定会撞上**的，别抱侥幸。
括号里是这条是在哪个环节被抓到的。

---

### 1. 按缩略图上的坐标反推原图坐标，永远差一截（量点）

**症状**：量出来的眼睛坐标怎么调都不对，改了三次还是偏。
**原因**：读图工具会把大图缩小到 1024 px 左右再给你看，而且**每次缩的比例不一样**。案例里是 0.6976 倍，
按截图上的像素反推原图，误差正好 1.43 倍。
**修法**：坐标**只**用程序量（连通域、颜色聚类、逐行剖面）；要肉眼看就用 `zoom.mjs` ——
它是固定倍率、按你给的矩形直接裁原图，看到的像素和原图一一对应。

### 2. 生图验收不严，做到走路才发现腿缝是填死的（生图）

**症状**：抠图时裙摆下沿到脚之间那一片是空的；填充/抹脸工具"漏"进去。
**原因**：模型把两条腿画成一整块，或者腿间有阴影把缝隙糊死。
**修法**：生图验收清单里加一条"两腿之间有干净的缝"。已填死的别硬修，**重出一张更便宜**。

### 3. ⭐ 整体下沉/摆动只作用在贴图上，五官错位（写 rig）

**症状**：站立时好看，**一坐下/一走路眼睛就飘到刘海上**，或者整张脸偏出脸框。
     用户的原话是"有时眼睛会错位"。
**原因**：把 `translate/rotate` 交给了 rig 的 `root` 变形器 —— 它只作用于 `<canvas>` 里的贴图；
而五官是另一层 SVG，不跟。坐着时 `frame.low` 到 29 单位，贴图下沉 25 单位，脸不动，于是五官浮在头顶。
**修法**：把贴图和五官放进**同一个父 `<g>`**，整体变换写在这个父节点上（`transform="translate(0 ty) rotate(a 128 256)"`，
和 rig 的旋转公式 `p' = pivot + t + R(a)·(p − pivot)` 等价）。单一真相，由构造保证不会错位。
**为什么之前没发现**：离线截图用了 `still=1`，此时 sway≈0、low≈0，变换整体为零 —— 只有实机漫游/坐下才暴露。

### 4. ⭐ 腿用"绕髋旋转"做走路，鞋子被拧成风车（写 rig）

**症状**：走路帧里鞋子变形、两只脚交叉、像风车。
**原因**：二头身腿很短、又大部分被裙摆挡住，绕髋旋转 ±20° 会把鞋子沿轴向拧过去。
**修法**：**纯平移 + 抬脚**。用 `frame.legs` 算 `dx`（前后差，乘 0.5 左右）、`lift`（抬脚高度），
只在裙摆下沿以下按 `smooth(hem, hem+20, y)` 衰减。

### 5. 头发 warp 幅度过大，甩出一个鼓包（写 rig）

**症状**：走动时头侧的发团鼓起一块，轮廓断了。
**原因**：warp 位移直接用了全身摆动量，没有按部位缩放/限幅。
**修法**：头发位移取"反向甩动 × 1.5 左右再 clamp"，并且 warp 的 rect 只覆盖头发；
`skirt`/`hair` 的 y 阈值都必须在脸框之下（脸在 y 53–92，阈值取 100 以上）。

### 6. ⭐ 眼睛比原画矮 / 两只眼像斗鸡眼（写五官）

**症状一**：眼睛整体比原画扁 7%，看着"没睁开"。
**原因**：kit 里表情给的 `rx/ry` 基准是 **16**，而你的眼是 `rx=8.6 / ry=9.2`（不等比）。
用一个 `k = rx/16` 同时缩 x 和 y，y 就被缩错了。
**修法**：`kx = rx/16`、`ky = ry/16` 分别用。
**症状二**：两眼一起朝鼻梁看。
**原因**：虹膜横向偏移里写了一项固定的"朝内偏"（案例里是 `- outS*0.5`），两只眼各偏 0.5 单位。
**修法**：虹膜位置只跟 `frame.look` 走，不要加固定偏移。

### 7. ⭐ 每次截图拍到的都不是同一个状态（离线验证）

**症状**：同一份代码，这次截图是睁眼，下次是闭眼；有时整张脸水平压扁、甚至镜像。
**原因**：① 眨眼是随机的，`frames` 恰好落在闭眼相位；② idle 的"东张西望"会把 `facing` 翻成 −1，
而它的过渡是 `lerp`，中途会渲染出 `scaleX≈0` 的压扁态 —— `layout().facing` 只报目标值，看不出来。
**修法**：截图一律 `still=1&noblink=1`；`still` 收尾时**再 `place()` 一次**把朝向瞬间拉回 +1；
专项查闭眼时反过来用 `blink=0.5`。

### 8. ⭐ CSS 里的 `fill:none` 静默盖掉元素上的 `fill`（写五官）

**症状**：上眼线整条不存在，眼睛像没睡醒；但代码里明明画了。
**原因**：为了统一描边风格，CSS 里写了 `.forge-figure .f-lash { fill: none }`。
CSS 声明**优先级高于** SVG 的 presentation attribute，于是填充带被整条抽空。
**修法**：CSS 只留 `stroke-linecap / stroke-linejoin`；需要纯描边的路径在元素上显式写 `fill="none"`。
**怎么发现的**：用 `probe=` 在页面里跑 `getComputedStyle(el).fill` —— 拿到 `"none"`，而 `getAttribute('fill')` 是 `"#0d0300"`。

### 9. ⭐ 抹脸把刘海啃出直角（抹五官）

**症状**：抹掉眼睛后，额头出现方块状的浅色块，刘海下沿出现直线切口。
**原因**：抹除掩码是"眼形超椭圆 ∪ 眉毛矩形带"，矩形带没有边界判断，直接把刘海一起抹了；
另外"向上找到刘海为止"的旧算法会把半透明的刘海边缘误判成皮肤。
**修法**：① 先做**头发掩码**（从脸框上沿泛洪"连到头顶的橙色"，黑色睫毛天然把眼睛隔开），
抹除与羽化都绕开它；② 眉毛带只吃"上方 7 px 还是皮肤"的深色像素；③ 羽化 3 px，并且羽化也不许溢进头发。

### 10. ⭐ 配置文件写成带 BOM 的 UTF-8，app 崩溃重启循环（改配置）

**症状**：改完 `config.json` 重启，一个窗口都没有，日志里是
`SyntaxError: Unexpected token '﻿'` / `Core 意外退出（退出码 1），3 秒后重启`。
**原因**：PowerShell 的 `Set-Content -Encoding utf8` 会加 BOM，而 `JSON.parse` 不认。
**修法**：写法固定成
`[System.IO.File]::WriteAllText($p, $s, (New-Object System.Text.UTF8Encoding($false)))`，
并用 `node -e "JSON.parse(require('fs').readFileSync(p,'utf8'))"` 做**严格**校验
（PowerShell 的 `ConvertFrom-Json` 容忍 BOM，会给假阳性）。

### 11. 改的是产物，不是源（打包）

**症状**：改了 `figure.js` 里的数值，跑一次 build 之后又变回去了。
**原因**：`figure.js` 是 `model.json` + `figure.body.part.js` **拼出来的**；
项目的 `figure-forge build` 还会用模板重新生成，直接覆盖手写代码。
**修法**：只改 `model.json` / `figure.body.part.js`，然后跑 `tools/compose.mjs`；
安装时手工拷 5 个文件，**不要**用 `build --install`。

### 12. 用字符串 replace 改 JSON，静默 no-op（改配置）

**症状**：明明改了，跑起来还是旧值；直到要交付才发现。
**原因**：`str.replace('"x": 1', '"x": 2')` 里但凡空格/键名/缩进不一致，就一个字符都不换，而且不报错。
**修法**：一律"解析 → 赋值 → 回写 → **回读**校验"（`manifest.mjs` / `compose.mjs` 里都有现成的回读断言）。

### 13. 自动识别五官不可信（量点）

**症状**：自动检测给出的眼睛坐标落在一缕头发上，置信度 0.96。
**原因**：五官检测靠颜色阈值，刘海、阴影、发丝的橙色和高光都会骗它；**置信度不等于正确**。
**修法**：识别只用来**出候选**，最终坐标必须程序复核（连通域面积/包围盒/均值色）或人工在 `zoom.mjs` 的固定倍率图上确认，
然后**写死**进 `measure.mjs` 的 `P`。

### 14. ⭐ 单张图切件做四肢，原位留洞（方案选择）

**症状**：切出腿/手后旋转，原本位置出现大洞（背景透出来），勉强补画就成了"两个头、两条腿"。
**原因**：切件动画要求原画里**被遮住的部分也被画出来**，而单张立绘没有。
**修法**：单张图的正解是**网格 warp**（`kind:'warp'`），不是切件。真要四肢自由活动，
就让生图模型**额外产出**分离的手臂/腿素材，或者换 Cubism（`.model3`）那一套。

### 15. 让生图模型批量出 19 套表情（方案选择）

**症状**：表情之间画风/瞳距/脸型都变了，切来切去像换了个角色。
**原因**：生成模型没有这层的跨图一致性保证。
**修法**：表情**用代码画**（同一套矢量眼 × 不同 `shape/dx/dy/ry`），风格天然一致；
生图只负责画一张脸。

### 16. ⭐ 闭眼像贴了一块白补丁（写五官）

**症状**：`blink=1` 时眼睛变成一块惨白椭圆 + 一条很淡的下缘线。
**原因**：眼皮填充用了单一皮肤色（`#fde3cf`，取自"眼上方"），而眼睛下方其实是腮红（`#ffc9ab`），
眼皮盖下来时色差就成了一张补丁。
**修法**：眼皮用**垂直渐变**，上色 `lid`、下色 `lid2`（各自按眼周实测取）；并且把"填充线"和"可见眼线"分开算：
填充线一定要盖住虹膜，眼线停在眼框 62% 处。

### 17. 虹膜填满整个眼框，眼睛没神（写五官）

**症状**：眼睛是一整块橙色，像贴纸；半闭时读成"没睡醒"。
**原因**：`iry` 取到了眼框高度（为了让眼睛"大"），没有眼白露出。
**修法**：`irx ≈ 0.85*rx`、`iry ≈ 0.72*ry`，虹膜略偏上，下方留月牙形眼白。

### 18. 呼吸的 ±1 就把嘴变成圆「o」（写五官）

**症状**：静止时嘴一直在"哦"，像惊讶。
**原因**：`gap` 是 0..64，阈值取太低（案例里一开始是 `(avg-43)/20`），说话/呼吸的微小抖动就跨过了阈值。
**修法**：阈值抬到 `(avg-54)/12` 一类，并把中性嘴的宽度收到 2 单位左右。

### 19. 下眼线一根 Q 曲线敷衍，中段横穿虹膜（写五官）

**症状**：眼睛中间有一道细黑线，像画错了。
**原因**：一根二次贝塞尔近似椭圆的下半弧，中段会浮在椭圆上方。
**修法**：按椭圆参数取 5 个点（22°/56°/90°/124°/158°）用两段曲线连，贴着椭圆走。

### 20. 笑眼/闭眼弧的顶点冲出眼框，像多长了一道眉毛（写五官）

**症状**：`happy` 表情的眼睛上方多一道粗弧线。
**原因**：闭眼弧的顶点取到了眼框外（0.95×ry），加粗描边后浮在脸上。
**修法**：顶点收到 0.46×ry，起止 y 用 `±0.15×ry`，粗细 `clamp(0.26*ry, 2, 3.2)`。

### 21. 抹脸用硬边超椭圆，渲染后方块感明显（抹五官）

**症状**：4× 下额头上有一块方形浅色区域，边缘是直的。
**原因**：掩码是"超椭圆 n=3"（上沿压平）+ 硬边填充，边界是折线；填充色又是逐行中位数，和局部色差一截。
**修法**：软边（3 px 羽化）+ 同行左右锚点插值（局部色）+ 与逐行中位数 50/50 混合。

### 22. 羽化溢进头发，刘海边缘发亮一圈（抹五官）

**症状**：抹完脸，刘海下沿多了一条浅色描边。
**原因**：羽化半径覆盖到了头发像素，而填充色是肤色。
**修法**：羽化循环里逐个像素查头发掩码，命中就把 alpha 归零。

### 23. 离线预览用 `file://` 打不开（离线验证）

**症状**：`import` 模块失败 / `fetch` 被 CORS 拦 / 贴图加载不出来。
**原因**：ES module 与 `fetch` 在 `file://` 下被安全策略限制。
**修法**：起一个本地静态服务（`tools/harness/main.cjs` 里就是 40 行 Node `http`），
把 Coopanion 的 `web/`、你的包目录、harness 页挂在三条路由上，再用 Electron 打开 `http://127.0.0.1:<port>/`。

### 24. 调试产物带本机绝对路径，一开源就泄露（交付）

**症状**：`_probe.json` / 各种 `_*.mjs` 里带 `E:\path\to\...`、用户名、内网路径。
**原因**：探针脚本习惯把源文件路径原样写进 JSON/日志。
**修法**：交付前扫一遍 `C:\Users\`、绝对盘符、用户名；`_` 开头的调试文件默认不进仓库。
交付物只放：源图、量点结果、手写 part、打好的包、报告、4 张图。
